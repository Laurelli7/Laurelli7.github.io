AI for software security

Making program analysis fast enough to matter.

I’m an undergraduate at the University of Chicago, advised by Kexin Pei. I work on putting language models to work inside classical program-analysis pipelines — fuzzing, symbolic execution, static reasoning — where the model proposes and a verifier decides.

Techniques like directed fuzzing and symbolic execution are precise but slow. They stall on the same structural obstacles: target states buried deep behind long chains of implicit preconditions, search spaces too large to enumerate, path explosion, constraints that a solver chews on for hours. Language models are good at exactly the thing those pipelines lack — reading unfamiliar code and guessing what matters — and bad at exactly the thing those pipelines guarantee, which is being right.

So the research question I keep returning to is where to put the seam. In our work on directed fuzzing, the model synthesizes intermediate predicates that act as milestones toward a target state, and a compiler plus symbolic execution proves each one only relaxes the target, so a wrong guess can never reject an input that would have found the bug. In our work on symbolic execution, the search is over code transformations themselves: learn which rewrites help, then apply them where the local context says they will. In both cases the model’s output space is deliberately narrow enough to be checked. That constraint is what makes the speedups usable rather than merely reported — and what turns them into real bugs in real software.

I’m especially interested in what else fits this shape: which parts of a static analyzer, a verifier, or a test generator can be handed to a model and still be trusted afterward.

  • Fuzzing Directed and coverage-guided search, progress-capturing feedback, agentic instrumentation, real-world vulnerability discovery.
  • Symbolic execution Path explosion, solver cost, learned code transformations, program representations tuned for the analysis rather than the CPU.
  • LLMs & verification Bounding model error with compilers, solvers, and symbolic checks; designing output spaces that can be validated.
